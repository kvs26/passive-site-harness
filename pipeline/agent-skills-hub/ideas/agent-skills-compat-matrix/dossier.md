# Dossier: Agent Skills Compatibility Matrix

**A per-skill × per-agent "will this skill work in my agent?" site whose whole pitch — "the only incumbent is a 0-star README a real site can out-rank" — was disproven this run: the compat question is now served on the SERP by several maintained sites (a per-agent skill directory with fit scores + compare, a maintained config-compat matrix, a thorough four-agent compat guide) and the scout's own incumbent has grown into a real static site with a 37×13 matrix, capability matrix, porting guide and an auto-refresh crawler — while the surviving per-cell long-tail targets near-zero-volume combos; confidence: medium (no Keyword Planner CSV).**

## Signal scorecard

**Demand: strong** — the "does skill/agent-skills X work in agent Y" question fans out per-agent in autocomplete, recurs across independent GitHub repos as a "host matrix" ask, and surfaces as a Bing People-Also-Ask cluster.
  - Autocomplete (Google, US, `scripts/fanout.py`, this run) fans the compat question per-agent: "do claude skills work in codex", "…in cursor", "…in copilot", "…in antigravity", "…in cowork", "…with gemini"; plus "claude code skills in github copilot", "claude code skills equivalent in github copilot", "claude skills equivalent in cursor", "install claude skills in cursor", "can i use claude skills in cursor", "does github copilot support claude skills", "agent skills google antigravity", "gemini agent skills antigravity".
  - Independent GitHub issues asking for exactly this matrix (fetched this run): "Audit current support for Codex, Claude Code, Hermes, GitHub Copilot CLI, Cursor, and Gemini CLI… Add a compatibility matrix to the README… The matrix distinguishes tested support from expected compatibility" — https://github.com/buhaistrikalo/envskill/issues/6 ; "Publish a versioned client matrix with exact client/version and transport scope… Keep an explicit unsupported/untested list; do not claim universal compatibility" (milestone "v2.4 — Ecosystem interoperability") — https://github.com/sun461941-hub/ai-project-copilot/issues/4 ; "a Skill that requires an external CLI, system package, supported product, or network access can appear ready to install without showing those requirements" — https://github.com/farion1231/cc-switch/issues/6559 .
  - Bing "People also ask" for the compat query (this run): "Does copilot support agent skills?", "What skills does cursor support?", "How do I use Claude code skills in cursor?", "How do I add skills to a copilot Repo?" — search-engine-recognised question cluster. (Actual search volume: unknown — no Keyword Planner CSV this run; Demand graded on recurrence + breadth, not volume.)

**SERP & competitor weakness: weak** — the compat question is held by maintained, substantive sites, not thin/AI-spun stubs; the results are not easily beatable.
  - openagentskill.com/agents (fetched this run): a per-agent skill directory — "9 AGENTS · 54 SHORTLISTED · 1.2K INDEXED", per-agent indexable pages (/agents/claude-code, /codex, /cursor, /github-copilot, /windsurf, /gemini, /cline, /amp, /antigravity), a per-skill "fit" score per agent, plus /compare, /rankings, /audits, weekly+monthly reports and a "State of Agent Skills 2026". 261 GitHub stars (github.com/Leon-Drq/openagentskill). This directly occupies the "which skill for my agent" space with real site pages (not a README).
  - aipm-registry.com/compatibility (fetched this run): "AI agent configuration compatibility matrix", **"Last checked: 28 August 2026"** (i.e. maintained), a "Which file works where" matrix across AGENTS.md / CLAUDE.md / Cursor rules / Agent Skill / MCP, backed by a registry+CLI product and a large guides hub (claude-code-skills-guide, agents-md-vs-claude-md-vs-cursor-rules, etc.).
  - vibekk.com/archives/agent-skills-cross-harness-compatibility (fetched this run): "Agent Skills Compatibility Across Four Coding Agents" (2026-07-22) — an "Official Compatibility Matrix" of per-agent project/user paths + invocation + extras for Codex/Claude Code/Gemini CLI/Copilot, a four-layer compatibility model, FAQ, and official-doc references. Thorough, not thin.

**Hook depth: weak** — the compat question genuinely matters to users, but the scout's specific differentiator ("only a 0-star README exists; every skill×agent cell becomes an indexable page a README can't rank for") is disproven, and the incumbent it was built against has itself become a real site.
  - The demand is real (see Demand), but it lands at the **agent-capability / format** level ("do claude skills work in copilot", "claude code skills in cursor") — exactly what vibekk (agent-capability matrix) and aipm (format matrix) and openagentskill (per-agent skill fit) already answer.
  - porex-bot/agent-skills-compat-matrix (re-fetched this run) has grown from the scout's "README, not a site" into a real static single-page web app deployed to GitHub Pages, with `data/skills.json` (per-cell `caveats`) + `data/agents.json`, a **37 skills × 13 agents** matrix, a separate **agent-capability matrix** (hooks, subagents, `context: fork`, slash commands, per-skill model override…), `docs/agents/` per-agent deep dives, a `porting-guide.md`, a schema+validator, and a **scheduled crawler** (github-actions bot, "chore(data): scheduled crawl update" 5 hours ago). Its README still opens with the idea's exact pitch verbatim — "One question every AI-coding user asks within a week: 'Will this skill work in my agent?'" — but it now ships the data model, capability matrix, per-agent docs and porting guide the idea proposed. (Still 0 stars, github.io — so weak on domain/traction, but no longer "just a README".)
  - Residual whitespace (SEO-friendly static per-(skill,agent) cell pages vs porex-bot's SPA and openagentskill's per-agent grouping) targets long-tail combos ("does <specific skill> work in <agent>") with no evidence of real search volume — a classic programmatic-SEO-over-near-zero-volume risk.

**Monetization paths: weak** — no competitor in the space monetizes via display ads; the money here is product/registry/SaaS, which a passive reference site cannot capture, and there is no Keyword Planner CPC to test a display/affiliate route.
  - The maintained players are product-led, not ad-led: openagentskill.com (registry + API + CLI, no display ads on the fetched page), aipm-registry.com (package-manager product + CLI, no display ads), vibekk.com (a general AI-strategy blog, not ad-stacked on this post). None runs AdSense/Ezoic/Mediavine on the pages fetched this run.
  - No Keyword Planner CSV this run, so no top-of-page bid to judge a display/affiliate route on — Monetization gets no CSV evidence piece and stays weak.

**Feasibility & maintenance: weak** — the build is trivially static, but the maintenance burden the scout flagged (gate-3 near-miss) is real and confirmed by the data sources themselves.
  - Build is easy and free: the inputs are public docs (agentskills.io spec + client-implementation guide; per-agent docs for Codex/Claude Code/Gemini CLI/Copilot), curated into build-time JSON→pages — exactly what porex-bot does (JSON + schema + generate_readme.py, static site).
  - But the data genuinely churns and needs dated re-verification: aipm stamps "Last checked: 28 August 2026", vibekk stamps its matrix "as of July 22, 2026" and warns "Product behavior can change after July 22, 2026", and porex-bot runs a **scheduled crawler** to keep cells current — three independent signals that per-agent feature/path support moves fast enough to require constant upkeep, not a quarterly refresh. A maintained crawler is itself ongoing engineering, not passive.

**Unique-data opportunity: weak** — every input is public and already structured by competitors; there is no data a passive site could hold that others can't derive.
  - The compat facts come straight from official docs (spec + per-agent docs) — porex-bot already derives them into `skills.json`/`agents.json` with per-cell caveats, and openagentskill computes per-skill "fit" scores. Any newcomer would be re-deriving the same public data others already publish.

**Confidence: medium** — SERP-weakness and hook are graded from multiple competitor sites fetched this run, and demand from ≥2 independent sources; but there is **no Keyword Planner CSV**, which caps confidence at medium and leaves actual search volume/CPC unknown. (Volume wouldn't change the verdict: the rejection is on gate-4/hook grounds, not on demand.)

## Monetization sketch

If built anyway, the only passive route would be display ads on per-agent / per-cell reference pages plus affiliate links to paid agent tiers — but no competitor in this space runs display ads (openagentskill, aipm are product/registry-led), the audience is developers (low display RPM), and there's no KP CPC to suggest a high-value keyword route. ## Risks & unknowns

- **Search volume/CPC — unknown.** No Keyword Planner CSV; Trends not fetched (prior 429). Doesn't change the verdict but is why confidence is medium, not high.
- **Per-cell long-tail volume — unknown, probably tiny.** No evidence anyone searches "does <specific skill> work in <agent>" at volume; the demand that exists is at the agent/format level, already served.
- **Gate 4 (no specific hook) — disproven this run.** The scout's "only a 0-star README" premise is false: openagentskill.com (per-agent directory + fit + compare, 261★), aipm-registry.com (maintained config matrix), vibekk.com (thorough 4-agent compat guide), plus the porex-bot incumbent itself now a real static site with the exact data model, capability matrix, per-agent docs and porting guide — all live.
- **Gate 3 (unmaintainable data) near-miss — confirmed as a real burden.** Three independent competitors date/crawl their compat data (aipm "last checked 28 Aug 2026", vibekk "as of July 22, 2026", porex-bot scheduled crawler), evidencing fast churn that needs constant upkeep.
- **Searched and came up empty:** no free per-keyword volume source (KP is the gap); DDG (`pain-fetch.py ddg` + browser) bot-challenged/empty this run (used Bing browser + built-in fetch instead); Google autocomplete throttled on alpha-expansion (used `--mode=plain`).
