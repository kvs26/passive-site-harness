# Visual / shareable asset kit (Pinterest + OG images + printable chart)

Type: prototype
Status: resolved
Blocked by: 03

## Question

Produce the **shareable visual assets** the spreading plays need — the static site currently emits none tailored for social. Decide the format and generate a first set:

- **Pinterest pin images** — tall (2:3) images per compatibility theme / long-tail page ("Does a DeWalt 20V misting fan run on your battery?"), on-brand (the new battery+bolt green mark), text-legible at thumbnail size. Feeds the Pinterest play (ticket 06).
- **Open Graph / social-share images** — so links pasted into Reddit/forums/Q&A render with a proper card, not a bare URL. (Check what the house template already emits for OG and whether per-page images are worth it.)
- **Printable / embeddable compat chart** — a genuinely useful one-page chart others might link or share. This is the seed of the "link-magnet" fog line on the map — build the minimum here; how far to push it graduates later.

Decide: generated by the agent as static files dropped into `sites/runs-on-your-battery-finder/public/`, vs. emitted by the build. Prefer whatever a future site can repeat cheaply. Deliver the first real images (not mockups) and confirm the build stays clean.

## Answer

**Generation approach:** static files, generated **offline by a script**, not emitted by the Astro
build — chosen over build-time generation to keep the shared house-template free of a new
image-rendering build dependency (satori/sharp/etc.). Wrote
[scripts/generate-social-assets.py](../../../sites/runs-on-your-battery-finder/scripts/generate-social-assets.py)
(Python + Pillow, not an npm dependency) that reads the site's real `catalog.json` directly — every
count/product name on every asset is real data, nothing invented. Cheap to repeat for a future site:
copy the script, edit the brand-color/copy `CONFIG` block plus the `PIN_THEMES` /
`CHART_PLATFORMS` / `CHART_CATEGORIES` picks, rerun. Generalizing it into a shared multi-site tool is
left for ticket 11 (extract-spread-site-skill) once a second site needs it.

**Assets generated** (all real renders, not mockups — see
[scripts/README.md](../../../sites/runs-on-your-battery-finder/scripts/README.md)):

- `public/og-cover.png` (1200x630) — default OG/Twitter card. This **fixes a live bug**:
  `SITE.ogImage` in `site.config.mjs` already pointed at `/og-cover.png`, but the file didn't exist,
  so every share card was silently broken. Confirmed the site emits only one default OG image
  (`BaseHead.astro`'s `ogImage` prop is per-page-overridable but nothing overrides it yet) — decided
  **per-page OG images aren't worth it for the first pass** (117 platform×category pages is a lot of
  renders for uncertain payoff); revisit only if a specific long-tail page shows real share traffic.
- `public/images/pins/<platform>-<category>.png` (1000x1500, 2:3, brand-green) — 10 pins across 5
  platforms (DeWalt, Milwaukee M18, Ryobi, Makita, HART) and 7 categories, mixing curiosity/novelty
  fits (a coffee maker, a bug zapper on Ryobi 18V ONE+) with mainstream high-count ones (jobsite fans,
  vacuums, speakers, inflators). Feeds the Pinterest play (ticket 06).
- `public/images/compat-chart.png` — a real platform×category compatibility matrix (9 core US
  platforms × 7 top categories, cell = verified-fit count, brand-green heat scale), computed live from
  `catalog.json`. This is the first, minimum cut of the "link-magnet" fog line — genuinely useful and
  link-worthy at this size; a richer embeddable/interactive widget stays fog (map's "Not yet
  specified") until a channel shows appetite for it.

Build confirmed clean after adding these (`npm run build` → 216 pages, no errors; `dist/og-cover.png`
and `dist/images/...` present, `og:image` meta resolves to the new file).
