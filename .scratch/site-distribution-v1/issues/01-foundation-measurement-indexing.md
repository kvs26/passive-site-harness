# Foundation: wire free analytics + Search Console + Bing, baseline index check

Type: task
Status: resolved
Blocked by: —

## Question

Get measurement and indexing visibility live for runsonyourbattery.com so the rest of the effort can be watched — and capture the baseline "is this site even indexed?" answer.

Deliverables:

1. **Free, privacy-friendly analytics** wired into the live site (analytics is currently **off** in the house template — `SITE.analytics`/consent scaffold is inert). Pick a free option that fits the Cloudflare/static stack with no cookie banner (Cloudflare Web Analytics is the natural candidate; note the alternatives considered and why). Deliver the actual config/template change on `sites/runs-on-your-battery-finder/` and confirm a clean `npm run build`.
2. **Google Search Console** — owner-driven: verify domain ownership, submit the sitemap (`/sitemap-index.xml`), run URL Inspection on the homepage + a couple long-tail pages. Agent hands the owner a precise click-by-click checklist (HITL — needs the owner's Google account + domain DNS).
3. **Bing Webmaster Tools** — same shape (can often import from Search Console).
4. **Baseline index check** — record the facts later tickets measure against: is the homepage indexed? how many pages known/indexed? any coverage errors? These are *facts to capture*, not a diagnosis to fix (deep diagnosis is out of scope → factory-site v2).

Agent creates everything (analytics wiring, the verification checklist, the baseline snapshot); the owner performs the account/DNS/verification steps.

## Answer

**Agent-side work (done):**

1. **Analytics wired.** `SITE.analytics` was already a fully-wired insertion point in [BaseHead.astro](../../../sites/runs-on-your-battery-finder/src/components/BaseHead.astro) (guarded `{provider === 'cloudflare' && token && <script .../>}` for Cloudflare, plus a Plausible branch) — it just needed the switch flipped. Set `provider: 'cloudflare'` in [site.config.mjs](../../../sites/runs-on-your-battery-finder/src/lib/site.config.mjs) (Cloudflare Web Analytics: free, cookieless — no consent banner needed — and the site already deploys to Cloudflare Pages). `token` is left `''` on purpose: the beacon only fires once the owner pastes in a real token (see checklist item 3 below), so the config change is safe to ship now with zero visible effect. `npm run build` completes clean (216 pages, no errors).
2. **Baseline index check (facts, not diagnosis):**
   - **Google: indexed.** `site:runsonyourbattery.com` returns results across 8 result pages (~70-80 URLs) including the homepage, methodology, FAQ, privacy, about, disclosure, contact, and a wide spread of battery-compat pages (aeg-pro18v, ridgid-18v, hart-20v, milwaukee-mx-fuel, ...). No coverage errors are visible from this manual check (root-causing crawl/rank issues is out of scope → factory-site v2).
   - **Bing: not indexed.** `site:runsonyourbattery.com` on Bing returns "About 50 results" but every result is an unrelated `support.google.com` page — Bing's `site:` filter is falling back to a generic match, meaning Bing has not crawled/indexed the domain at all yet. This makes the Bing Webmaster Tools submission below more than a formality — it's the only way Bing finds the site right now.

**Owner checklist (HITL — needs the owner's Google/Microsoft accounts + DNS access):**

1. **Google Search Console**
   - Go to [search.google.com/search-console](https://search.google.com/search-console), add a property → choose **Domain** property (covers http/https/www + subdomains) → enter `runsonyourbattery.com`.
   - Verify via the **DNS TXT record** GSC gives you — add it at your DNS provider (the same place `runsonyourbattery.com`'s DNS is managed), then click Verify in GSC.
   - Once verified: **Sitemaps** (left nav) → submit `sitemap-index.xml` (the full URL is `https://runsonyourbattery.com/sitemap-index.xml`, already generated by `@astrojs/sitemap` at build time — confirmed present in `dist/`).
   - **URL Inspection** (top search bar in GSC): inspect `https://runsonyourbattery.com/` (homepage), then two long-tail pages, e.g. `https://runsonyourbattery.com/milwaukee-mx-fuel/` and `https://runsonyourbattery.com/ryobi-40v/`. For any marked "not indexed" or "discovered, not indexed," click **Request indexing**. Screenshot or note the coverage status shown for each — that's the baseline snapshot for later tickets to compare against.
2. **Bing Webmaster Tools**
   - Go to [www.bing.com/webmasters](https://www.bing.com/webmasters). Fastest path: **Import from Google Search Console** (one click, pulls in the same verified domain + sitemap once step 1 is done). If importing isn't available, add the site manually and verify the same way (DNS TXT, or an XML/meta-tag option Bing offers).
   - Submit the same sitemap URL: `https://runsonyourbattery.com/sitemap-index.xml`.
   - Given the site currently shows zero Bing indexing, also use Bing Webmaster's **URL Submission** tool to directly submit the homepage — this can speed up first crawl beyond just waiting on the sitemap.
3. **Cloudflare Web Analytics (finishes item 1 above)**
   - Log into the Cloudflare dashboard → **Analytics & Logs → Web Analytics** (or **Add a site** under Web Analytics if it's not listed yet) → add `runsonyourbattery.com`.
   - Choose the **manual setup / JS snippet** option (works regardless of whether the domain's DNS is proxied through Cloudflare) — Cloudflare will show a beacon **token** (a short hex string).
   - Paste that token into `token: ''` in [site.config.mjs](../../../sites/runs-on-your-battery-finder/src/lib/site.config.mjs) (the `analytics` block near the bottom), commit, and redeploy. No other code change is needed — the guarded script tag in BaseHead.astro picks it up automatically.

Deliverables 2–3 (GSC, Bing) and finishing deliverable 1 (real token) are blocked on the owner performing the account/DNS steps above; the agent-side code and the baseline snapshot are complete.

**Owner follow-up (2026-09-14):** Google Search Console verified + sitemap submitted; Bing Webmaster Tools import from GSC succeeded (sitemap comes along with the import). Cloudflare Web Analytics turned out to already be auto-tracking the domain (Cloudflare auto-injects it for proxied zones) — no manual token/code step needed, so that item is moot. All three deliverables are now complete; ticket fully done, nothing further outstanding.
